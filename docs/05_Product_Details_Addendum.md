# 05_Anisekai_Product_Details_Addendum_v1.0

# Purpose

This document supplements the previous four specifications with
product-level rules that Claude must follow.

------------------------------------------------------------------------

# Mandatory Rule

The approved homepage design is locked.

No existing homepage widget, section or major layout may be removed
unless explicitly requested by the project owner.

Widgets may be enhanced but not deleted.

------------------------------------------------------------------------

# Homepage Mapping

Every homepage widget must link to a dedicated detail page.

Examples:

-   Hero Banner → Featured Article
-   Breaking Leaks → Anime Leaks
-   Episode Hub → Episodes
-   TCG Hub → TCG
-   Trends → Trends
-   Latest News → News

Homepage is a dashboard only.

------------------------------------------------------------------------

# Widget Philosophy

Every major page should also use dashboard widgets instead of a simple
article list.

Each section should contain multiple information cards.

------------------------------------------------------------------------

# CasRadar Component Reuse

When an equivalent CasRadar component already exists, adapt it instead
of rebuilding.

Examples:

-   Dashboard
-   Homepage Builder
-   Media Library
-   Scheduler
-   SEO Manager
-   Analytics
-   User Management
-   Permission System
-   AI Workflow

------------------------------------------------------------------------

# Homepage Profile Card

Guest: - Login - Register

Member:

-   Avatar
-   Username
-   Level
-   EXP
-   Badge
-   Current Pet
-   Notifications

------------------------------------------------------------------------

# Advertisement

Support configurable ad positions.

Ads should be manageable from CMS.

Possible locations:

-   Hero Banner
-   Sidebar
-   Between Widgets
-   Article Pages
-   Footer

Support enabling/disabling per location.

------------------------------------------------------------------------

# AI Image Review

AI-generated images are never published automatically.

Editors must approve, reject or regenerate.

------------------------------------------------------------------------

# Permission Levels

Support:

-   Super Admin
-   Administrator
-   Editor
-   Moderator
-   Author

Permissions should be configurable.

------------------------------------------------------------------------

# Future Modules

Backend architecture must allow future modules without redesign.

Examples:

-   Virtual Pet
-   Marketplace
-   Community
-   Forum
-   Mobile App API
-   Premium Membership
-   Achievements
-   Events

------------------------------------------------------------------------

# Final Requirement

If there is any conflict between implementation convenience and these
specifications, these specifications take priority.
